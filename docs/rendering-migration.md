# 原生绘图迁移框架

本文记录固定布局图片从 Playwright/HTMLRender 迁移到原生 SVG 渲染的既定方案。迁移以缩短插件可控部分的响应时间为目标，不包含 osu! API 等外部网络耗时，也不通过缓存最终成绩图来换取速度。

## 目标与边界

运行时架构固定为：

```text
业务数据
  -> 纯数据 Payload
  -> 并发资源准备（头像、封面、Mod、字体）
  -> SVG 布局
  -> resvg 栅格化
  -> Pillow 最终图片处理与 JPEG/PNG 编码
```

- SVG 负责全部布局：文字、色块、边框、圆角、裁切、渐变、图表和组件定位。
- resvg 负责把 SVG 栅格化，不启动浏览器进程。
- Pillow 只处理 SVG 不适合承担的位图工作，例如缩略、模糊、亮度/饱和度调整、格式标准化和最终编码；不使用 Pillow 手工排整张卡片。
- 不缓存包含实时成绩数据的最终成图。只缓存可复用的源资源和与数据无关的处理中间产物。
- 对外绘图函数签名和返回类型保持不变，matcher、AI 工具和其他调用方不需要跟着迁移。
- 迁移期间保留现有 HTML/CSS 模板作为视觉基准和开发对照，不作为已迁移入口的运行时回退路径。

## 性能预算

性能验收区分外部请求和插件本地工作。热资源场景下，固定卡片的本地预算为：

| 阶段 | 目标 |
| --- | ---: |
| Payload 构建及普通计算 | <= 150 ms |
| 本地资源读取和预处理 | <= 150 ms |
| SVG 生成及 resvg 栅格化 | <= 400 ms |
| 最终编码 | <= 100 ms |
| 插件可控总耗时 | <= 800 ms |

冷资源首次下载单独记录，不用它掩盖热路径回归。任何必须等待的外部资源都要有明确超时和占位图，不能无限拖住出图。

## 分层设计

### 1. Payload 层

每种图片先把 API/数据库模型转换为只包含基础类型的 payload。Payload builder 可以读取业务模型，但不能绘图、下载图片或依赖浏览器。

这一层负责：

- stable/lazer、模式、Mod 和自定义速度等业务语义；
- PP、星数、命中统计、排名变化等展示值；
- 标题、日期、数字和单位的统一格式化；
- 列表截断、排序、空状态与动态画布高度。

### 2. Resource 层

资源解析器批量、并发地准备图片，并返回统一的本地字节或 data URI。缓存的是资源，不是最终成图。

- 玩家头像、谱师头像和战队图标按稳定 ID 缓存，并设置更新时间。
- 谱面封面按 beatmapset ID 缓存；背景预处理结果可以按源文件指纹缓存。
- `.osu` 文件继续以 API checksum 校验，避免旧谱面导致星数错误。
- bundled Mod 与字体资源进程内复用，不在每张卡中重复读盘或编码。
- 同一张图需要的资源使用 `asyncio.gather` 并发准备；同一 URL/路径的并发请求使用 singleflight 合并。
- 资源失败时返回明确占位图，并记录日志；头像等装饰资源不能阻塞核心信息出图。

### 3. Layout 层

每个 renderer 是纯 SVG builder：输入完整 payload 与已准备资源，输出固定宽度、动态高度的 SVG 字符串。

公共布局能力至少包括：

- 字体选择、文本宽度测量、缩小字号、单行省略和多行截断；
- 头像、圆形裁切、描边、封面裁切和背景遮罩；
- 支持者心形、排名、星数、Mod 和自定义速度标签；
- stable/lazer 标识；
- 数字、百分比、PP、日期和时长格式；
- 卡片、分栏、表头、统计条、趋势折线和动态列表行；
- 可复用且 ID 安全的 `clipPath`、mask 和 gradient 定义。

组件只接收显示值与几何参数，不直接读取 Pydantic 模型或发起 I/O。文本位置必须通过字体度量计算，不能依赖浏览器自动布局，也不能靠某个测试用户名的固定坐标。

### 4. Raster 层

统一 rasterizer 接收 SVG、目标尺寸与输出格式：

- resvg 显式加载项目字体并关闭系统字体扫描，保证不同部署环境一致；
- CPU 密集的栅格化和编码通过 `asyncio.to_thread` 离开事件循环；
- 默认直接按最终像素尺寸渲染，只有确实出现锯齿的局部才提高采样率；
- JPEG 输出统一质量与色彩模式，透明背景图才使用 PNG；
- 不允许 renderer 各自偷偷启动 Playwright。

## 目录规划

迁移时按下列职责拆分；文件名可在实现阶段微调，但边界不变：

```text
draw/
  rendering/
    assets.py          # 资源缓存、singleflight、图片标准化
    typography.py      # 字体、度量、截断和排版
    components.py      # 通用 SVG 组件
    raster.py          # resvg + Pillow 编码
    models.py          # 共享 payload 类型
  score_svg.py         # 单张成绩图（已迁移，后续下沉公共能力）
  bp_svg.py            # BP/成绩图片列表
  score_history_svg.py # 单谱面成绩历史
  map_svg.py           # map 与 bmap 共享组件
  info_svg.py          # 玩家信息
```

不要先造一个能够描述任意 UI 的大型场景树。公共层只抽取至少被两个 renderer 使用、且几何语义稳定的组件，具体版式继续留在各自 builder 中。

## 迁移顺序

### 第一阶段：巩固单张成绩图

当前单张成绩图已采用 SVG/resvg 主路径。先将其中字体、图片和 raster 逻辑下沉到公共层，保持现有视觉修正：

- 支持者心形连续排列；
- 谱师头像圆形描边；
- 总 PP、谱面标题和难度名正确对齐；
- stable/lazer 与自定义 DT/NC/HT 速度正确展示。

### 第二阶段：BP 列表与成绩历史

两者共享最多的成绩行/卡片组件，优先一起迁移：

- BP、PFM、TBP、PR/RE 列表和 AI 多成绩列表继续复用同一 `draw_pfm` 入口；
- 保留现有 5/6 列密度切换、动态高度和列表上限；
- 成绩历史保留最佳成绩标识、判定统计、Mod、星数与 stable/lazer；
- PP 计算批量移出绘图循环的阻塞路径，并复用已解码谱面与难度属性。

### 第三阶段：map 与 bmap

二者共享封面身份区、谱师信息、星数色带和统计组件：

- `map` 保留转谱、Mod 后属性、原始/变化值和 SS PP；
- `bmap` 保留最多 20 个难度、动态高度和多谱师头像；
- 所有难度作者一致时不重复显示头像；作者不同时头像在独立左对齐列中，不挤压难度名起始位置；
- 模式字形如果项目字体无法稳定覆盖，改用随包 SVG path，不回退系统 emoji。

### 第四阶段：个人信息

个人信息结构最多，最后迁移：

- 保留数据库历史对比、排名趋势、等级、评级分布、徽章和 BP10；
- 玩家信息 API 与 BP10 请求尽可能并发；
- 徽章和 BP 封面均走资源层，单个资源失败不能中止整图；
- 趋势图直接生成 SVG path，不引入图表运行时。

### 后续阶段

只有在上述固定卡片稳定后再评估其他入口：推荐图、排名图、rating 和比赛历史也适合相同架构。ECharts、需要网页导航的截图、动画和交互式谱面预览仍可使用 Playwright，除非另有独立替代方案；本次迁移不强行删除 htmlrender 依赖。

## 正确性与兼容性

- 星数和 PP 只由业务计算层给出，renderer 不重复推导。
- map 转谱必须使用目标 ruleset 的谱面属性；Mod 后值与原始值同时保留。
- NC 与 DT 去重规则、自定义速度标签和 stable/lazer 判定集中在 payload 层。
- 所有列表继续遵守现有筛选、排序、范围和“单条结果发单图”的业务行为。
- 无排名、无 PP、无 team、无徽章、无头像、长用户名、CJK/拉丁混排和极端数值都必须有确定布局。
- 避免运行时读取远程 URL 的 SVG `<image>`；渲染前转换为本地字节/data URI，确保截图时没有网络等待。

## 测试与验收

每迁移一个 renderer，都需要同时通过以下检查：

1. Payload 单元测试：业务字段、筛选、模式、Mod、速度和客户端版本。
2. 结构测试：SVG 尺寸、动态高度、clip ID 唯一、必要文字与组件存在。
3. 真实输出：四种模式以及长标题、多 Mod、多谱师等边界样例。
4. 视觉回归：与迁移前基准图并排检查；允许抗锯齿差异，不允许信息缺失、错位或截断退化。
5. 性能 profile：分别报告 API、资源、PP/星数、SVG、raster 和编码耗时，至少包含一次冷资源和连续三次热资源。
6. 事件循环检查：栅格化与大型图片处理不在 async 主线程执行。
7. `uvx ruff format --check --diff`、`uvx ruff check` 和完整 pytest。

一个入口只有在视觉、正确性、异常降级和热路径性能全部通过后，才删除运行时 Playwright 路径。迁移提交按阶段拆分，避免把四类大型模板一次性混进同一提交。

## 完成定义

本轮固定卡片迁移完成时，应满足：

- 单张成绩、BP 列表、成绩历史、map、bmap 和 info 的运行时不创建浏览器页面；
- 热资源时每张图的插件可控耗时稳定小于 800 ms，CI 或低性能机器记录单独阈值；
- 外部 API 或首次资源下载较慢时，profile 能明确指出耗时来源；
- 现有调用方、命令语义和图片信息量不退化；
- htmlrender 仅由仍真正需要浏览器/JavaScript 的绘图入口使用。
